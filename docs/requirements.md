# 需求规格说明书

## 1. 项目概述
项目名称：基于大语言模型的 GPU 算子自动生成与测试平台。平台目标是形成算子任务描述、代码生成、执行、正确性评估、性能评估、保存和展示的完整流程。

## 2. 第一阶段目标
阶段名称：平台基础框架与模拟闭环开发。支持一个 `vector_add` 示例，不依赖真实模型 API 和 GPU。

## 3. 典型用例
1. 用户选择 `vector_add`，填写 shape 和 dtype。
2. 前端向后端提交任务。
3. 后端创建任务并返回唯一 `task_id`。
4. 后端调用模拟生成器，得到预设代码。
5. 后端调用模拟执行器，得到受控模拟输出。
6. 正确性模块比较参考输出和执行输出。
7. 性能模块记录明确标记的模拟耗时。
8. SQLite 保存任务及结果，前端展示详情。

## 4. 功能需求

| 编号 | 功能 | 要求 |
|---|---|---|
| FR-01 | 创建任务 | 接收 operator、description、shape、dtype |
| FR-02 | 任务编号 | 生成唯一 task_id |
| FR-03 | 状态管理 | 使用统一状态流转 |
| FR-04 | 代码生成 | 模拟生成器返回预设示例代码 |
| FR-05 | 执行 | 模拟执行器返回受控结果，不执行任意生成代码 |
| FR-06 | 正确性 | 比较参考输出和实际输出 |
| FR-07 | 性能 | 记录模拟耗时，`is_simulated=true` |
| FR-08 | 结果查询 | 查询任务、代码、执行和评估结果 |
| FR-09 | 持久化 | SQLite 保存数据 |
| FR-10 | 前端 | 展示任务列表、状态、代码和结果 |

## 5. 非功能需求
- 模块通过明确的数据契约通信。
- API 使用统一 JSON 格式。
- 失败时返回错误码和可读说明。
- 模拟性能不能展示为真实 GPU 测量值。
- 每个核心模块至少有成功和失败测试。
- 密钥不得硬编码进仓库。

## 6. 第一阶段范围
**包含：** `vector_add`、FastAPI、模拟生成/执行、正确性比较、模拟性能记录、SQLite、基础前端、自动化测试。

**不包含：** 真实模型 API、真实 GPU 编译执行、多种国产 GPU 兼容承诺、自动调优、复杂 Agent、分布式任务队列、用户权限系统、真实性能结论。

## 7. 验收标准
- [ ] 可以提交 vector_add 并获得 task_id。
- [ ] 可以查询任务状态和详情。
- [ ] 可以看到模拟生成代码和模拟执行结果。
- [ ] 正确性评估能区分通过与失败。
- [ ] 性能记录带 `is_simulated=true`。
- [ ] 服务重启后仍能从 SQLite 查询任务。
- [ ] 前端展示状态、代码和评估结果。
- [ ] 自动化测试通过。
- [ ] 文档明确说明未进行真实 GPU/API 测试。

## 8. 后续阶段
资源确定后，分别验证模型 API、GPU 软件栈和最小算子执行，再按数据契约替换生成器、执行器和性能测量实现。


## 开发环境与依赖要求

### 1. Python 版本

项目统一使用 Python 3.11.x。

建议组员尽量统一具体 Python 小版本，减少不同环境下的兼容性问题。

### 2. 核心依赖

| 依赖 | 版本要求 | 用途 |
|---|---|---|
| Python | 3.11.x | 项目开发语言 |
| Pydantic | >=2.7,<3.0 | 共享数据模型定义、数据校验和序列化 |
| FastAPI | >=0.115,<1.0 | Backend API 服务 |
| Uvicorn | >=0.30,<1.0 | ASGI 服务运行 |
| pytest | >=8,<9 | 单元测试 |
| httpx | >=0.27,<1.0 | API 测试 |

### 3. Pydantic 使用要求

本项目统一使用 Pydantic v2。

所有共享数据模型放在根目录的 `contracts/` 中，并使用统一的基础模型。

禁止在不同业务模块中重复定义相同的共享数据模型。

项目代码使用 Pydantic v2 的接口，例如：

- `BaseModel`
- `Field`
- `field_validator`
- `model_validator`
- `ConfigDict`
- `model_dump()`
- `model_dump_json()`

不要混用 Pydantic v1 的旧式校验接口。
