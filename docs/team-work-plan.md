# 第一阶段五人分工与并行协作计划

## 1. 主责分配

| 人员 | 主责 | 交付物 |
|---|---|---|
| 组长（你） | 架构、任务管理 API、流程编排、集成 | 架构文档、后端任务流程、集成记录 |
| 组员 A | 前端页面、API 联调与接口测试 | 页面、接口测试用例 |
| 组员 B | 生成模块 | `agent/generator.py`、生成测试 |
| 组员 C | 执行模块 | `executor/runner.py`、执行测试 |
| 组员 D | 正确性评估和 SQLite 存储 | `correctness.py`、数据库访问、相关测试 |

组长另负责一个相对简单的独立任务：`evaluator/benchmark.py` 的模拟性能记录。第一阶段只记录带 `is_simulated=true` 的模拟值，不负责真实 GPU 性能测试。

## 2. 测试不要全部压给 D
- B：生成模块成功/失败测试。
- C：执行模块成功/失败测试。
- D：正确性比较测试、存储测试。
- 组长：任务状态流转、流程集成、模拟性能记录测试。
- A：API 请求/响应测试、前端联调。
- 全员：端到端验收和交叉审查。

## 3. 各阶段全员参与

### 阶段一：数据契约
- 组长：总体架构、任务状态、API 约定。
- A：确认页面需要的请求和响应字段。
- B：生成模块输入输出契约。
- C：执行模块输入输出契约。
- D：正确性和存储数据契约。
- 全员：检查字段名称和类型是否一致。

### 阶段二：并行编码
- 组长：后端任务管理、流程编排、模拟性能记录。
- A：前端页面、接口测试。
- B：模拟生成器和单元测试。
- C：模拟执行器和单元测试。
- D：正确性比较、SQLite 存储和单元测试。
- 全员按契约独立开发。

### 阶段三：集成
- 组长：连接 API、生成、执行、评估和存储。
- A：页面/API 联调。
- B：检查生成结果字段。
- C：检查执行结果字段和失败处理。
- D：检查评估结果及数据库记录。
- 全员：端到端测试。

### 阶段四：测试验收
每人负责自己模块的成功和失败测试；组长负责完整流程；A 负责 API 测试；全员共同演示和修复问题。

## 4. 并行规则
1. 先冻结 `data-contracts.md` 第一版。
2. 各模块可使用固定样例或 stub 独立开发。
3. B、C 不必互相等待。
4. 字段变更必须同步文档并通知相关成员。
5. 使用 feature 分支，通过 Pull Request 合并到 `dev`。
6. `main` 保持稳定可演示版本。

## 5. 阶段交付要求
每人每阶段至少提交一个可检查产物：文档、代码、测试、审查记录或演示记录。
