# 实验记录与评测规范

> 本文件记录实验方法与结果索引。详细数据可按实验单独保存为 CSV/JSON，并在此处链接。

## 1. 实验原则

- 先验证正确性，再进行正式性能比较。
- 对比实验尽量固定输入、硬件、软件版本和测量方法。
- 保存失败记录，不只保留成功案例。
- 区分实测数据、估计值和占位示例。
- 不通过挑选单次最佳结果来夸大性能。
- 每条结果应可追溯到任务配置、代码版本和运行环境。

## 2. 每次实验必须记录的信息

| 类别 | 记录内容 |
|---|---|
| 基本信息 | 实验 ID、日期、执行者、关联 Issue/PR |
| 研究目的 | 本次要验证的问题或假设 |
| 任务配置 | 算子、输入形状、数据类型、后端 |
| 模型信息 | 模型名称/版本、提示词版本、生成参数（可获得时） |
| 代码信息 | 代码版本、Git commit、候选代码存放位置 |
| 环境信息 | 操作系统、GPU/加速器、驱动、框架和编译器版本 |
| 正确性 | 参考实现、测试用例、容差、通过/失败 |
| 性能 | 预热与测量次数、计时方式、延迟统计值 |
| 结论 | 结果解释、异常、限制、下一步 |

## 3. 性能指标

加速比：

`speedup = baseline_latency / candidate_latency`

其中两种延迟必须使用相同单位、相同测试条件和可比的计时方法。候选实现不正确时，不应报告其为有效优化结果。

建议保留每次测量值，并报告中位数或预先约定的统计量。对于短时 GPU Kernel，应注意预热、同步和测量噪声。

## 6. 结果文件建议

可在仓库中使用 `experiments/` 目录保存小型、可公开的配置与汇总数据。大型原始数据、私密日志或受限数据应按团队约定保存在合适的位置，不要未经检查直接提交。

## 7. 实验审查清单

- [ ] 输入和环境记录完整
- [ ] 代码版本可追溯
- [ ] 正确性测试先于正式性能比较
- [ ] 计时方法和重复次数明确
- [ ] 失败案例也有记录
- [ ] 结论没有超出数据支持范围
